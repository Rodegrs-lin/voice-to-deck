# 录制与独立音效交接

## 适用范围

本技能产出网页，不自己渲染视频。用户要成片时，把页面交给 [`html-to-mp4-recording`](https://github.com/Rodegrs-lin/html-to-mp4-recording)；独立音效轨按本文件后半段做。已验收的网页交付物保持不变，源 HTML 不因录制而修改。

## 录制前置

- 先冻结最终 HTML 并记录 SHA256；录制结束后复核哈希，哈希变了说明录的不是同一版。
- 优先确定性逐帧渲染（由 `record_vite.mjs` 完成）：按时间 t 设置页面状态 → 截图 → 推给 ffmpeg `image2pipe`。不使用实时录屏，避免掉帧。
- 帧率、分辨率、时长在开录前确定，不从画面尺寸反推。

## 交给 html-to-mp4-recording

- 本包页面是 **Vite/React 打包页（形态 B）**，用 `record_vite.mjs`。用 `record_page.mjs`（形态 A）会报 `No timed scenes found`。
- 页面必须暴露 `window.__rec = { duration, pages, renderAt, events }`，且 `__rec.pages[i].start` 与 `timeline.pages[i].start` 相差 < 0.02s——录制器会断言，不满足直接退出。
- `?review=1` 只渲染、不自播：关掉自动 play，关掉 `t < 5 ? 5 : t` 这类兜底钳位（它会把片头五秒悄悄替换掉）。
- 页面里的 `<video>` 交给录制器：暴露 `window.__videoEl` 和 `window.__videoLocalT = t - page.start`，不要自己 `play()`。逐帧比实时慢约 3 倍，自己播的视频会跑完好几轮，每次录制结果都不一样。
- 逐帧截图成立的前提是动效全部由时间推导。若还残留墙钟动画，每帧会拍到随机相位，成片抖动，且与单帧复核对不上。
- 录制耗时 ≈ 成片时长 × 2.5（实测 8.6–12 fps），务必后台跑。
- **录前必跑 `scripts/audit-motion.mjs`**：逐帧录制忠实到不会报错，页尾空转、某一拍没变化都会被原样录进成片。

## 视口与尺寸

- 页面用 `transform: scale(min(w/1920, h/1080))` 自适应时，截图必须定死视口 1920×1080，否则比例失真。

## 录制侧隐藏控件

- 播放门控遮罩（“开始 / 继续播放”）、`review` 调试徽标、调试 HUD 都会进入画面。
- 只在录制页面注入 CSS 隐藏实际节点，不改源文件；隐藏后抽首帧确认，别只看最后一帧。
- 门控节点名不要猜。先在源里定位真实选择器，再写隐藏规则；猜错会得到“改了但遮罩还在”的假修复。

## 独立音效 MP3

- 事件源取页边界、章节切换（`section` 变化点）与片尾（约 92% 时长处）。
- 同一套事件同时驱动独立 MP3 与成片混音，避免两条轨对不上。
- 音效不写入 HTML，不改源音频；独立轨单独交付，可被用户另行使用。

## 混音与验收

- `amix=inputs=2:duration=first:normalize=0`，视频流 `-c:v copy`，音频重编码为 AAC 立体声。
- 峰值不高于 -3 dB；实测 -5 dB 可接受，不得削波。
- 验收项：时长对齐、分辨率、帧率、总帧数、首/中/尾抽帧、无黑帧、无残留控件。

## 规模参考

- 868.96 秒 → 26,069 帧 @30fps，约 14:29。
- 逐帧渲染耗时远高于视频时长，属正常；不要为提速改成实时录屏。
