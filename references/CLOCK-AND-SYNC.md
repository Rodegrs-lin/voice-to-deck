# 时钟与音画同步（双契约）

这一页是这个包里最贵的一页。**音画对不上，十次里有九次不是时间没校，是计时的元素和出声的元素不是同一个。**

## 一条硬规则

> **时钟必须等于声源。** 出声的是谁，就用谁的 `currentTime` 当时间轴。另一个媒体只做参考，靠阈值校正跟随。

违背它的后果很具体：只要计时用的是一条静音音轨、出声用的是另一条媒体（哪怕是同一条口播的副本），两块媒体各自的缓冲、seek、解码时序就彼此独立。视频卡一下，画面就跑到声音前面；音频起播慢 80ms，画面就整体错位。**逐页去校时间是治不好的**，因为漂移是随时发生的，不是一次性偏移。

## 两种模式，二选一，写进 `timeline.json` 的 `clock` 字段

| | **A · 静音模式** `clock: "mp3"` | **B · 有声模式** `clock: "dh(video)"` |
|---|---|---|
| 谁出声 | 没有人声（后期合轨） | 出声的那条媒体自己（数字人音轨 / 配音视频） |
| 谁计时 | 静音 MP3 | **同一条出声媒体的 `currentTime`** |
| `BIAS` 偏移 | **0.10s**（MP3 内容比视频晚，实测恒定，读时钟时减掉） | **0**（同一个元素，无需偏移） |
| 另一条媒体 | 不存在 | 静音 MP3，`muted` + `volume = 0`，**只做时间映射与总长校验** |
| 音量 | 全部 0 | 声源 0.72 起（1.0 会压住音效轨） |
| 典型用途 | 录屏、后期配音、投稿 | 直接播给人看、发给客户 |

`timeline.json` 里同时记 `presenter.mode`（如 `pip-circle-bottom-left`）与 `presenter.muted`，让检查脚本能判断当前是哪一档。

## 实现要点（三处，缺一不可）

```ts
const BIAS = SOUND ? 0 : 0.10                    // 只有静音模式需要补偿
const clock = () => (SOUND ? videoRef.current : audioRef.current)
const readClock = (c) => c.currentTime - BIAS
const seekClock = (c, at) => { c.currentTime = at + BIAS }
```

1. **`clock()` 返回的是「正在出声的那个元素」**，不是固定的某个 ref。这是整条规则落地的地方。
2. **两轨跟随校正**：`if (Math.abs(v.currentTime - a.currentTime) > 0.3) v.currentTime = a.currentTime`。阈值取 0.3s——小于它属于正常解码抖动，去纠反而抖；大于它说明真的漂了。
3. **`BIAS` 必须实测，不能猜**。做法：静音模式下让两条媒体各自跑到同一时刻，读 `video.currentTime - audio.currentTime`，取稳定段的均值。本项目实测恒定为 +0.10s。

## 为什么不能靠 CSS / 定时器补

- 用 `setTimeout` 追帧会让漂移累积，跑十分钟能差出好几秒。
- 用「画面按 MP3 走、声音按视频走」这种双源方案，等于让两个独立时钟赛跑，物理上无法长期对齐。

## 起播：单文件版必须默认有声

打包成「双击打开」的单文件时，注入一个默认值，否则用户双击后是静音的，会以为坏了：

```js
window.__DEFAULT_SOUND__ = true
```

运行时优先读 URL 参数，其次读这个默认值：

```ts
const SOUND = qs.has('sound') ? qs.get('sound') === '1' : !!window.__DEFAULT_SOUND__
```

- `?sound=1` 强制有声（审片、演示）
- `?sound=0` 强制静音（录屏取干净画面）
- 不带参数 → 用打包时的默认值

**注意**：`?sound=1` 是**参数**，不是页面上的按钮。不要做音量滑块或静音开关——那是另一个层面的问题，且会破坏逐帧渲染的确定性。

## 打包时路径要改相对

`file://` 下 `/audio/x.mp3` 会指向盘符根目录，必然加载失败。构建后把所有运行时资源路径从 `"/media/`、`"/audio/`、`"/assets/` 改写成 `"./media/`、`"./audio/`、`"./assets/`，否则双击打开是黑屏静音。

## 怎么验（两个都必须过）

**① 时钟归属**（有声模式）：起服务后开 `?auto=1&sound=1`，每 3 秒采一次，同时读视频与 MP3 的 `currentTime` 和 `paused`：

```
页面            视频t   视频暂停  MP3t    MP3暂停
step1           12.40   false     12.40  true
```

合格判据：**视频在走、MP3 是 `paused: true`**，两条的 `t` 差 ≤ 0.3s。若 MP3 也在走，说明时钟没切过去。

**② 静音模式补偿**：`?auto=1&sound=0`，比对画面元素落定时刻与口播句首，偏差应 ≤ 0.3s。若整体偏早 0.1s 左右，是 `BIAS` 没减。

两个模式都要跑一遍全片到结尾，确认 `t` 与 `audioDuration` 差值 < 0.5s。

## 与固定页面录制的关系

- 静音模式：页面出声为 0，录屏拿到的是干净画面，人声与音效后期合轨。
- 有声模式：录屏会把人声录进去。若还要叠加音效轨，注意别重复——音效轨里不应再含人声。

## 常见误判

- **「画面比声音早一点点」不一定是 `BIAS` 错**。先用 ① 确认时钟归属，时钟错了，调 `BIAS` 只会越调越偏。
- **「只有某一页对不上」** 多半是内容对齐问题（页面在讲 A、口播在讲 B），不是时钟问题。见 `SKILL.md` 里「页与口播的内容对齐必须单独验」。
- **「MP3 里有声、视频也出声」** 是双声源：两条口播叠在一起会听出回声感。务必只让一条出声。
