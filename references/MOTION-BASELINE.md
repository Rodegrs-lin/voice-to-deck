# 动效底线（PPT 档）

这个包做的是**动态 PPT**，不是动效片。所以它对动效的要求只有一条主线：

> **每一页都要有东西在动，但不是每一句都要变出一个新图案。**

判据按「页」和「拍」来算，不按句算。

---

## 两条 skill 的分工

|  | **voice-to-deck**（本包） | **anchor-driven-demo-page** |
|---|---|---|
| 形态 | 一页一个画面，页内 3–5 个拍 | 一页 6–9 块，每块绑一个句号 |
| 密度 | 一个拍 ≈ 1–3 句口播 | 一句口播 = 一个动作点 |
| 动效目标 | 讲清楚、可录、可播 | 高密度、有戏、抓人 |
| 动效判据 | 每拍有变化 + 每页有实物锚点 | 每句都有变化（覆盖率 ≥90%） |
| 典型用在 | 教程、拆解、给客户看的说明片 | 观点片、钩子片、要炫的片子 |

**要高密度转译（每句一个图案、遮住字也能看出这句话），请用 `anchor-driven-demo-page`。** 在这个包里硬加那种密度，会变成满屏乱动——一页 20 秒配 10 个图案，观众跟不上。

---

## 五条判据

### 1 · 每页至少一个实物锚点

一张真实的图（截图、数据图、产品照），或一个真画出来的对象（器件、界面、流程节点）。

**不合格**：整页只有文字 + 色块 + 装饰线。这种页质检查不出来，人一眼看出是半成品。

### 2 · 每页 3–5 个拍，每个拍都要有一次可见变化

变化必须是「某个量在推移」，而不是整块出现：

| 算数 | 不算数 |
|---|---|
| 数字从 0 滚到 280 | `opacity: 0 → 1` |
| 折线从左到右画出来 | 整块卡片淡入 |
| 条宽从 0 涨到 68% | 文字 `translateY` 上移落位 |
| 列表逐条点亮（第 3 条亮起时第 1 条还在） | 四条同时出现 |
| 圆环从 0 长到 74% | 圆环直接以终值出现 |
| 遮罩擦开一段文案 | 文案整体渐显 |

判据一句话：**把这一拍的两帧截图并排看，除了「有 / 没有」，还能看出「多 / 少」吗？** 看不出多少，就不算。

### 3 · 页尾 4 秒内必须有东西在动

最后一个拍落定 → 页尾，如果超过 **4 秒** 画面完全静止，那一段就是死画面。

两种修法：
- 把最后一拍的锚点推到该页**最后一句**
- 加一条页内进度线，随 `t` 持续推进

### 4 · 全片只允许一次主角动作

转折、结论、反差落点才配强动作（缩放冲击、描边生长、马克笔划线）。

**其余页一律常规推进**——但「常规推进」不等于「只会淡入」，见第 2 条。选了主角动作就把它当主角，别每页都来一下。

### 5 · 动效全部由 `t` 算，不用 CSS 动画

`animation` / `@keyframes` / `transition` 走的是合成器墙钟，暂停后照样继续跑。典型症状是「画面停住了，但背景一直在动」。

持续运动一律由同一个时间变量推导成静态 `transform` / `opacity`；时间不变，值就必须不变。

## 一页的动效账

以 19 页 / 385 秒的项目实测为参照：

- 平均每页 **20 秒**
- 平均每页 **4.4 个拍**（84 个拍 / 19 页）
- 平均每拍 **4.5 秒**

也就是说：**一个拍大概配 1–3 句口播**。如果某一页你数出来 10 个拍，那不是拍，那是把每句当拍了——那种密度请换 `anchor-driven-demo-page`。

## 什么时候主动降级

内容本身不适合动的时候（清单、对照表、引文页），允许**整页静止但结构完整**，前提是：

- 这一页的停留时间 < 8 秒
- 前后各有一页在动
- 在 `visual-direction.md` 的 avoid list 里记一笔

连续两页静止 = 观众开始划手机。

## 什么时候该换 skill

出现下面任一条，说明这个内容需要的是动效片，不是动态 PPT：

1. 口播密度高到「一句话一个新信息」（一页 10 句以上，每句都在讲不同东西）
2. 用户要的效果是「炫」「抓人」「钩子」
3. 每一句都值得单独配一个图案

这时候不要在本包里加密度硬凑，直接换 `anchor-driven-demo-page`。

## 门禁

判据写在文档里没人会读，所以它们都变成了会报错的检查。

```bash
node scripts/audit-motion.mjs --timeline timeline.json --src presentation/src

# 想验「每拍都有变化」，必须给 --url（页面要暴露 ?review=1 下的 window.__setT）
node scripts/audit-motion.mjs --timeline timeline.json --src presentation/src \
  --url "http://127.0.0.1:4321/index.html?review=1"

# 源码里如果还留着试验支线（overlay 试验、参考实现、备份），一定要排除
node scripts/audit-motion.mjs --timeline timeline.json --src presentation/src --exclude ovl,lab,backup
```

**`--exclude` 不是可选项。** 项目源码里常年躺着别人的、以前的、试验的东西。不设边界时，那些分支自己的毛病会被算到这次交付头上——实测过一次：`--src` 扫到 `ovl/`（一条 overlay 试验支线），报了 6 处 `@keyframes`，而主链路一个都没有。**排除之后 M2 直接 PASS。**

| 门禁 | 查什么 | 判据 | 缺参数时 |
|---|---|---|---|
| **M1** | 页尾不是死画面 | 最后一个拍 `end` → 页 `end` ≤ 4s | 必查 |
| **M2** | 无 CSS 动画驱动运动 | 源码里没有 `@keyframes` / `animation:` | 需 `--src` |
| **M3** | 每页有实物锚点 | 源码里存在 `img` / `svg` / `video` / `canvas` / `backgroundImage` | 需 `--src`，且只是弱信号 |
| **M4** | 每拍都有可见变化 | 同一拍隔 0.35s 两帧，差异 ≥ 0.15% | 需 `--url` + playwright-core |
| **M5** | 页密度属于 PPT 档 | 每页 ≤ 8 个拍 | 必查 |

三条读法：

1. **`SKIP` 不等于通过。** M4 跑不了（没浏览器）时，那一条就是**没验**，报告会单独列出来。不许把 SKIP 算进 PASS。
2. **M3 只能证明「用过图形」**，不能证明「每页都有」。逐页确认还得靠渲染后看。
3. **M4 只证明「变了」，不证明「是量在推移」。** 淡入也会让帧差超过阈值。要判「量在推移」，只能按第一节的对照表**人工看两帧**——把这一拍的两帧截图并排，问「除了有/没有，还能不能看出多/少」。

这三条是故意留在机器外面的：机器能判的都判了，判不了的就明确说判不了，不假装。
